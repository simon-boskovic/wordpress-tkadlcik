# Radost v pohybu (Daniel Tkadlčík, tai-chi / qigong) — local WordPress + Elementor build

## What this is
The site of Daniel Tkadlčík, a Czech tai-chi/qigong instructor ("Radost v pohybu"), built and tested **locally in Docker** with the same pipeline and techniques as `../wordpress-adamus-main` (martinadamus.cz): Hello Elementor + child theme `tkadlcik`, pages generated as Elementor JSON and written by WP-CLI, The SEO Framework for meta/sitemap, a plugin-free static page cache, security headers, and cookie consent like martinadamus R45: Complianz 7.5.5 (strict opt-in) + Site Kit 1.188.0, whose Google tag stays blocked until consent to statistics (see "Cookie consent and analytics"). No redirects plugin (redirects live in a mu-plugin).

## Talking to WordPress (`wp tk …`)
All in `wp-content/mu-plugins/tk-build/class-tk-build-command.php`:
- `doctor` — read-only report (versions, theme, plugins, pages, kit, Elementor options, cache, headers).
- `site-setup` — runs **before WordPress loads** (`@when before_wp_load`; the class is required early via `wp-cli.yml`, `WP_CLI_CONFIG_PATH=/project/wp-cli.yml` in the wpcli service): `wp core install` if not installed (admin from `wp-secrets.env`), then `wp tk site-configure` (local only unless `--allow-non-local`): Hello Elementor + child theme `tkadlcik` (warns while missing/incomplete), Elementor + The SEO Framework + the pinned Complianz 7.5.5 and Site Kit 1.188.0 (another version is replaced with `--force`), deletes akismet/hello, cs_CZ + translations, Europe/Prague, `/%postname%/`, comments/pings closed, deletes untouched default content.
- `page-upsert --dir=/project/build/pages` — adamus format `{slug, title, elements, status?, template?, scripts?: [nav|tabs|reveal], front_page?, preload?}`; meta `_tk_scripts`, `_tk_preload`; unchanged pages are `[ok]` and not written; backups of overwritten `_elementor_data` in `/backups/layouts/`; front page = `front_page: true` else slug `domu`.
- `media-import` — `build/media.json` (`[{file, alt}]`) or every image in `/project/client-img` → WebP (max edge 1600, q80), idempotent, `--replace`; `--files-dir=` imports non-image files unchanged (no WebP, same name).
- `kit-setup` — our own Elementor kit (meta `_tk_kit`, palette/typography from `build/kit.json` if present), element cache off, optimized image loading off, background lazy-load off, Google Fonts off, CSS print method external, `e_optimized_markup` active.
- `seo-setup` — TSF titles/descriptions/robots/canonical/OG from `build/seo.json`, TSF JSON-LD off, sitemap on, `title_location` right.
- `consent-setup [--dry-run]` — Complianz cookie consent: only the keys in `tk-build/consent.php` are compared/changed (on production always dry-run first); saving the banner regenerates `uploads/complianz/css/banner-1-optin.css` with `assets/css/consent-banner.css` as its Custom CSS — re-run after editing that file. `doctor` reports "Consent".
- `cache-setup [--mode=rewrite|php|off] [--host=] [--edge-ttl=] [--precompressed=yes|no] [--print-htaccess]`, `cache-purge`, `cache-warm [--concurrency=4] [--skip-verify]`, `cache-status`, `headers-setup [--remove] [--print-htaccess]`.

## Page cache (`mu-plugins/tk-page-cache/`, no plugin)
- Every published page and post is stored by WordPress itself as `wp-content/cache/tk-page/<path>/index.html` + `.gz` (+ `.br` only with ext-brotli — not in the Docker image; Apache then brotli-compresses the plain file on the fly for br-only clients). Files live in the WordPress volume.
- Serving, fastest first: the `.htaccess` block `# BEGIN TK Page Cache` (before WordPress's block) → `X-TK-Cache: HIT`, no PHP; the `wp-content/advanced-cache.php` drop-in (needs `WP_CACHE`, set in `WORDPRESS_CONFIG_EXTRA`) → `HIT-PHP`, also for tracking-only queries (`utm_*`, `fbclid`, …); otherwise WordPress (`MISS`/`STORED`, or `BYPASS (<reason>)`).
- **404 never stored**: `BYPASS (404)` + WordPress's `no-store`.
- Bypass: non-GET/HEAD, other host, the warm header, cookies `wordpress_logged_in_*`/`wordpress_sec_*`/`wp-postpass_*`/`comment_author_*`/`wordpress_no_cache`/`tk_nocache`, paths that are not lowercase slug segments ending in `/` or start with `wp-`, feed/embed/trackback/search, any non-tracking query. Never-cached paths: `TK_PC_NOCACHE_PATHS` in `lib.php` (empty).
- HTML headers: cached pages `public, max-age=0, must-revalidate` + ETag/Last-Modified (304 on revalidation); anything WordPress renders gets `private`. `robots.txt`/sitemaps `public, max-age=3600`; REST `private, no-cache`. Static assets: one year (css/js/woff2), 30 days (images).
- Safety net: `save_post` etc. (page/post/attachment/elementor_library/menus/blocks; not posts created during a front-end render), relevant options (title, home, permalinks, front page, TSF settings, Elementor options), theme switch, plugin changes, `elementor flush_css`, menu/term edits → one purge at the end of the request + WP-Cron re-warm 30 s later. `.ht-generation` discards captures that started before a purge. `.ht-stamp` (home option + salts + build fingerprint of theme/mu-plugin mtimes) purges after a migration or file-only deploy.
- wp-admin: *Nástroje → Stránková cache* (purge + warm button).
- Debug: `curl -sI http://localhost:8020/`; force a WordPress render with `-H 'Cookie: tk_nocache=1'`. Local TTFB ~3 ms HIT.
- Rules in lockstep: `tk-page-cache/lib.php` ↔ its JS twin `build/lib/cache-rules.mjs`; `build/test/cache-cases.json` runs against both (`cache-rules.test.mjs`, `page-cache-test.php`). Change a rule → change both + add a case. Patterns anchored with `$` use PCRE's `D` modifier (else `$` also matches before a trailing newline, which JS never does).
- Checks: `node build/cache-check.mjs --base=URL [--mode=php]` (every page HIT with gzip/br/ETag/304, bypass matrix from the JS twin, aliases/404 never stored, cache dir 404, crawler/REST Cache-Control); `page-cache.int.mjs` (STORED → HIT/HIT-PHP, HEAD never stores, purge on save, scheme/stamp purges). Apache's mod_deflate ignores an uppercase `Q=0` (it gzips the plain file anyway); our rules/drop-in honour it.

## Cookie consent and analytics (port of martinadamus R45)
- **Complianz 7.5.5 strict opt-in** (EU, consent 365 days, categories Funkční + Statistické only) with **Site Kit 1.188.0**'s Google tag **blocked until consent to statistics**. Complianz's own Site Kit integration only whitelists the tag (+ "advanced" Consent Mode: gtag.js would ping Google before consent), so `consent-setup` turns it off, sets statistics = Google Analytics, "Complianz adds the script" = no, **Consent Mode = no**: the cookie blocker turns `<script id="google_gtagjs-js" src="…googletagmanager.com/gtag/js?id=…">` into `type="text/plain" data-category="statistics" data-cmplz-src`, Complianz's JS loads it only after consent; the inline gtag() queue stays (no request, no cookie). Cookie policy = URL `/zasady-ochrany-osobnich-udaju/#cookies` (no Complianz-generated policy page), link title "Zásady cookies".
- Locally Site Kit is never connected: `tk-local.php` feeds `googlesitekit_setup_gtag` the fake id `GT-LOCALTEST`. Production: the client's Google account/GA4 property at go-live (`docs/go-live-requirements.md` #21–24).
- Banner (dark-only site): Czech texts (martinadamus wording); colours only from the theme tokens (`var(--surface)` card with 24 px radius, `--ink` text, `--muted`, `--line`, Přijmout/Odmítnout equal `--accent` pills with `--on-accent` text, Zobrazit preference outline pill, `--focus` ring; dark fallbacks in the CSS, Complianz's `--cmplz_*` variables re-pointed to them on the banner; the hex values in `consent.php` are only Complianz's fallback), Geist, ≥ 44 px controls, close × inside the padding; manage-consent tab hidden (the footer link reopens it). CSS: `assets/css/consent-banner.css` → `consent-setup` → Complianz's generated file, printed inline in `@layer tk` by `tk_inline_style_tag()`.
- Theme glue `inc/consent.php`: Complianz's hand-printed `.cmplz-hidden` `<style>` moved into the layer; complianz.js gets an empty `data:` stylesheet (else it injects an unlayered `<link>`); no Site Kit generator meta; `assets/js/consent.js` (inlined at the end of `<body>`, i.e. before the deferred complianz.js: `[data-tk-consent-open]` → `cmplz_set_banner_status('show')`; withdrawing statistics clears `_ga*` and reloads; `_ga*` without consent removed after DOMContentLoaded; focus-trap release for a banner hidden by the browser). Footer bar: copyright + operator line from `site.json` `business` (nothing if absent) and "Nastavení cookies" (`.tk-ft-consent`, only while Complianz is active; no-JS fallback = the privacy page `#cookies`); reference patch **D8**.
- Click-to-load maps and YouTube facades are not declared to Complianz: the visitor's click is the request (with everything refused too).
- **Page cache:** Complianz's blocker rewrites the page in an output-buffer callback; `tk_pc_nest_complianz_buffer()` (`cache.php`) restarts it inside the capture buffer, otherwise the stored file holds the tag unblocked (proven). Complianz sends no `Set-Cookie` on page responses; `cmplz_*` cookies are not bypass cookies (case in `cache-cases.json`). Changing `cmplz_options`/`complianz_options_integrations` purges the cache.
- **Complianz banner cache (martinadamus R49):** `cmplz_get_cookiebanner()` caches banner objects in the global `$cmplz_banner`, and `cmplz_update_all_banners()` (via `finish_wizard()` and option-save hooks) re-saves them; `consent-setup` therefore saves the banner after those calls and empties the cache. Complianz's `save()` needs `cmplz_user_can_manage()` (an administrator is set first).

## Gotchas
- **Never `docker compose down -v` without `./db-export.sh`.**
- WP-CLI subcommand docblocks: no line may start with `@` unless it's a real tag (`@subcommand`, `@when`) — it breaks the synopsis parsing.
- The command class is loaded twice (wp-cli.yml early, mu-plugin later): it is guarded by the constant `TK_BUILD_COMMAND_LOADED`, **not** `class_exists()` (PHP declares the class at compile time, so a class_exists guard at the top always returns early).
- Local WP-Cron cannot reach `http://localhost:8020` from inside the container; the scheduled re-warm only runs via `./wp.sh cron event run tk_page_cache_warm`. `cache-warm` uses `TK_PAGE_CACHE_CONNECT_TO=wordpress:80`.
- Editing theme/mu-plugin files changes the build fingerprint: the next WordPress request purges the cache (a warm running at that moment reports `purged-meanwhile`; re-run `./wp.sh tk cache-warm`).
- Author archives and `/wp-json/wp/v2/users` are 404 for anonymous visitors (`tk-hardening.php`): never link to author pages.

## CSS subsets and image sizes
- Elementor's frontend CSS is served as a curated subset (`wp-content/themes/tkadlcik/assets/css/subsets/`, sha1-pinned in `manifest.json`; an Elementor update falls back to the full file). After changing pages run `node build/css-subset.mjs --check`; if stale, `node build/css-subset.mjs` and commit. Cookie `tk_nocache=full-css` renders with the full CSS (never cached) for debugging.
- `TK_BASE=http://localhost:8020 node --test build/test/responsive-sizes.int.mjs` checks the `sizes`/srcset picks for the photos. Run it on its own, never in the same `node --test` call as `page-cache.int.mjs` (that one purges the cache mid-run).
- Headless browser: the Chrome for Testing build can crash on this Mac; `TK_BROWSER=~/Library/Caches/ms-playwright/chromium_headless_shell-1223/chrome-headless-shell-mac-arm64/chrome-headless-shell` makes the harness use the headless shell.
